# AGENTS.md
## Kerb demo video constitution

This file applies only to the demo video production work in `docs/demo_video`, `scripts/demo-video`, and the generated `artifacts/demo-video` workspace.

The root `AGENTS.md` still wins on product truth, safety, vocabulary, provenance, testnet/mainnet claims, and repository integrity.

## Mission

Create the strongest possible remote hackathon demo for Kerb while remaining fully faithful to the working product.

The film must make a judge understand three things without needing the README:

1. Tokenized stocks can trade continuously while executable exit liquidity and underlying market sessions do not.
2. Kerb turns market time and real executable liquidity into reproducible credit terms.
3. Kerb Credit proves those terms can govern a live borrow, Last Call, and permissionless Cure on X Layer testnet, while the risk plane itself is on X Layer mainnet.

Kerb is the market-time risk layer. Kerb Credit is the reference consumer and proof, not the whole product.

## Non-negotiable film rules

1. Never fabricate a UI state, transaction, figure, contract result, market state, or research result.
2. Never alter a number inside captured UI footage.
3. Never use AI-generated substitute product footage.
4. Real recordings remain the visual backbone.
5. If a read-only recording is weak, Claude may re-record the live public route with Playwright or a browser capture.
6. If a wallet transaction recording is weak, prefer the existing source clips. Re-record a transaction only when an operator-provided test wallet environment already exists and the action is on X Layer testnet.
7. Use `06_LAST_CALL_AND_CURE.mov.mp4` as the primary hero source. `06b...mp4` is salvage footage only.
8. `11_MINTING...mp4` is optional. Use it only if the borrow flow is incomprehensible without setup context.
9. The final runtime must be between 2:00 and 4:00. Preferred target is 3:18. Never exceed 3:45.
10. Use the phrase `Never lend more than you can liquidate.` exactly once.
11. State the testnet and unaudited limitation once, near the end.
12. Keep the cursor visible when it adds meaning. Remove or crop it only when it is idle or distracting.
13. Do not accelerate human interaction so aggressively that the demo feels staged. Normal UI segments may be trimmed. Long network waits may be removed with a clean match cut.
14. No generic crypto motifs, coins, chains, neon grids, HUD clutter, glitch spam, fake terminals, or fake code.
15. No em dash characters in files committed under `docs/`.

## Brand language

The visual grammar comes from Kerb itself:

- warm ivory
- near black
- graphite
- muted moss
- restrained brass
- thin structural rules
- seams
- market state rails
- controlled apertures
- exact spacing
- deliberate motion

Motion should feel engineered and architectural, not promotional.

## Editorial principle

Every second must perform one of four jobs:

- establish the problem
- prove the measurement
- demonstrate the credit behavior
- prove reproducibility and extensibility

If a shot does none of those, remove it.

## Decision hierarchy

When there is tension between polish and truth, truth wins.

When there is tension between showing more features and telling a clearer story, clarity wins.

When there is tension between motion graphics and the real product, the real product wins.

When there is tension between a beautiful pause and information density, preserve the pause if the preceding idea needs time to land.

## Hard stop conditions

Do not export final if any of these is true:

- the Last Call and Cure sequence is unclear
- the film can be mistaken for a lending app rather than a risk layer
- the X Layer integration is not visible or spoken
- the mainnet versus testnet distinction is unclear
- the film contains a figure not supported by the current repo evidence or visible source footage
- narration fights the music
- text overlays are unreadable on a laptop at normal playback size
- the final render has missing frames, clipping, stretched UI, or visible capture artifacts
